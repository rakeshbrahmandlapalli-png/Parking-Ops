# Attendance essentials — release checklist

At the inherited checkpoint, setup 130 was the only reported live change.
Step 4 uses synthetic local data only; no live state is read or changed.
Private pilot: the explicitly linked individual RAKESH account at TAKEOFF.
No other employee may be enrolled or receive Attendance notifications.

## Supported release path

Apply 131 (explicit identity), 132 (tester gate), then 134 (namespaced existing
Attendance engine). **Do not apply 133**: it is a superseded clocking prototype,
retained temporarily with its tests for comparison. The supported app uses only
the `aero_*` clocking engine in 134, not `attendance_shifts` from that prototype.

134 is generated by `node src/build-attendance.mjs` from the existing Attendance
schema and `src/attendance-shared-gates.sql`. Review generated SQL before applying.
It has one transaction and does not configure a timer or push destination.
Existing parking companies remain canonical; `aero_companies` stores Attendance
settings for the same company UUID, with a foreign key to parking companies.

demo rendering/navigation, not real Supabase Auth, PostgREST or phone delivery.

## Before deployment

1. Complete manager browser journeys and later live Auth/API acceptance. Step 4
   staff journeys against the isolated test backend have passed at all four widths.
2. Complete manager staff-enrolment policy/UI for the private pilot; never reuse
   the legacy staff function's password/ban operations for shared parking users.
3. Verify the real API relationship embeds; local PostgreSQL cannot prove PostgREST.
4. Record existing parking function/settings hashes and verify rollback against
   a throwaway copy. Keep source project and backups.
5. Deploy only new Edge Functions, explicitly retaining JWT settings for all old
   functions. `aero-access` validates the caller and pilot gate itself;
   `aero-send-push` rechecks recipient eligibility through service-only RPC.
6. Configure `aero_push_config` only after verifying the generated sender and
   existing VAPID configuration; never point it to the old project's sender.
7. Deploy Attendance in opt-in pilot mode. Deploy the gated parking entry only
   after the new app is ready. Enrol only the confirmed RAKESH/TAKEOFF IDs, using
   his existing Auth UUID; do not change passwords or create a duplicate identity.
8. Set the real worksite from verified GPS coordinates through the Sites screen.
9. Verify that an ordinary TAKEOFF staff account cannot enter, read data or receive
   notifications. Verify your complete clock/break/timesheet/correction/export path.

## Release stops

Do not enable pilot access until the above gates pass. Revoking tester access
stops new clock-ins; `aero_open_shift`, `aero_end_break` and `aero_clock_out` remain
restricted to the authenticated owner of an open shift so it can be finished.
Retain all attendance records. No old-project deletion is part of this release.
